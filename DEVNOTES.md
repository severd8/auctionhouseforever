# AuctionHouse Forever — developer notes

An addon for **World of Warcraft: Forever** (interface 16001, client 1.60.x) that makes the retail-style Auction House (`Blizzard_AuctionHouseUI`, `AuctionHouseFrame`) resizable, movable and scalable, with draggable column widths and an adjustable category list. It changes only layout, size and styling.

- Author: `severd8`.
- CurseForge project ID: **1742416** (in the `.toc` as `X-Curse-Project-ID`).
- License: MIT.

## Files

- `AuctionHouseForever.toc` — `## Version: @project-version@` is filled in by the packager from the git tag. Don't hard-code a version.
- `Theme.lua` — **the shared look, the same file in all the Forever addons** (TauntMaster, ToppedOff, Outfitter, BattleText, AuctionHouse). Change it in one repo, then copy it to the others. It finds its own addon's name and logo from the folder name, in `BRANDS`; this repo added the `AuctionHouseForever` entry, so copy it to the other four. Loaded first. Don't use Blizzard templates in a window with this look.
- `Core.lua` — settings (`DEFAULTS`, `LIMITS`, `PrepareSettings`, `PrepareCharSettings`, `ColumnState`), resets, setup when `Blizzard_AuctionHouseUI` loads (`OnAuctionHouseLoaded`), slash commands (`/ahf`, `/auctionhouseforever`, list in `COMMANDS`) and events.
- `Layout.lua` — the window: size and corner grip (double-click: default size; quick sizes are `AHF.SIZE_PRESETS` in `Core.lua`), moving by the title bar, scale, lock, the category list's width (`ApplySidebar`, `StretchCategoryButtons`). `ApplyLayout()` puts every saved setting on the frame; call it freely.
- `Columns.lua` — columns: divider grips on each list's header row; after every layout `ArrangeColumns` puts the saved settings back (hidden columns and order via `ShapeColumns`, then widths); row text size (`ApplyRowFonts`, `SetRowFontSize`); the settings window's API (`KnownColumnLists`, `ListColumns`, `SetColumnShown`, `MoveColumn`, `ResetColumnLayout`); `ResetColumns`. The lists are in `COLUMN_LISTS` (key and path under `AuctionHouseFrame`).
- `Extra.lua` — AuctionHouse Forever's own columns (`EXTRA_COLUMNS`: iLvl, Req, Type, Vendor on the search results; Per unit, Seller on an item's auctions), added to the table builder after Blizzard's layout (`AddExtraColumns`, once per new layout, after the Name column or the last column with a header) so they're hidden, moved and resized like any other; what each cell shows (`CellText`, from the row's data, `GetItemInfo` and `GetItemInfoInstant`; cells waiting for item info refill on `GET_ITEM_INFO_RECEIVED`); the cell template's code (`AuctionHouseForeverCellMixin`); sorting the search results by our columns (`SortBrowseResults`: the loaded `browseResults` re-sorted after each `UpdateBrowseResults`; click areas over our headers, `PlaceSortButtons`, since Blizzard's header buttons are pooled and shared; Blizzard's `SetSortOrder` clears ours; the sort is saved in `db.browseSort` and lasts across searches, and `AHF:BrowseSort()` ignores it while its column is hidden; a post-hook on `UpdateHeaders`, which Blizzard calls on each search, hides the game's own arrow again); red text for items the player can't use (`AHF:CanUse`: a red line below the name in `C_TooltipInfo.GetItemByID`, or only the level without it; cached per item and cleared on level up and skill / spell / recipe learned; `db.markUnusable`); and the **Columns** button on the search bar (`SetupColumnsButton`, a `WowStyle1FilterDropdownTemplate` dropdown like Blizzard's Filter button; menu in `BuildColumnsMenu`, for the list on screen, `CurrentListKey`). A column's `hidden = true` makes it start hidden (`DefaultHidden`; `ColumnState().hidden[name]` false/true overrides it).
- `Cells.xml` — `AuctionHouseForeverCellTemplate`, the cell of our columns (a text cell; Blizzard's `Number14FontWhite` when the game has it).
- `Options.lua` — the settings window (`Theme.Window`: Window, Columns, Show & Order, General tabs; list names in `LIST_LABELS`) and the Interface Options entry (`RegisterSettingsCategory`: a page with an "Open settings" button). Every control gets hover help through `TipAll`; a new control must too (a test checks). "Reset to default" needs a second click within 4 seconds (`ConfirmButton`). `AHF.optionsRefresh` repaints the open window when a setting changes elsewhere.
- `News.lua` — short "What's new" lines for the splash screen, newest first. **Add an entry with every release**; its top version must match the top of `CHANGELOG.md` (a test checks this).
- `Libs/` — bundled libraries, loaded first: `LibStub` (public domain) and `LibAHTab` (MIT, plusmouse; the library Auctionator makes its tabs with; its LICENSE is kept beside it). LibStub keeps one copy when several addons ship it.
- `Tab.lua` — the **AH Forever** tab at the bottom of the Auction House, made with LibAHTab (`CreateTab` with our panel as the attached frame), so it matches Auctionator's tabs and lines up after them; the library shows the panel when the tab is selected and hides it for any other tab. The panel's OnShow / OnHide move the settings window in (`Embed`: no X / Close, logo clear of the portrait) and back out (`Release`). Without the library, `OwnTab` makes a tab placed after the last one in the row, skipping any that are anchored to ours. Escape, `/ahf` again (back to the Buy tab) or closing the Auction House closes it. `/ahf` uses the tab while the Auction House is open.
- `Report.lua` — `/ahf debug`'s window: `ReportText` (version, `GetBuildInfo`, `TabDebug`, settings, screen, sort, other loaded Auction House addons from `AuctionAddOns`) in a read-only multi-line EditBox, selected for Ctrl+C.
- `Splash.lua` — welcome / what's new window. Shows once per new `News.lua` version (and on first install) unless turned off; `/ahf news` opens it.
- `Media/logo.tga` — 128×128, 32-bit TGA with alpha: a gold coin and a gavel in the gold ring, the same medallion style as the other Forever addons. Used through `Theme.LOGO` everywhere. Sources in `art/` (not shipped): `icon.svg` (the medallion), `logo.svg` (the framed logo with the name on a banner) and `logo.png` (1024×1024, for the CurseForge project icon and the README). Re-export `Media/logo.tga` from `icon.svg` if the logo changes.
- `tests/` — offline test suite (not shipped). `render.lua` / `render.py` draw the windows for a visual check. `wowstub.lua` fakes the WoW API and the parts of the Auction House the addon touches (`FakeAuctionHouse()`, a table builder with Blizzard's width math); `run_tests.lua` holds the scenarios; `run.lua` runs them.
- `CHANGELOG.md` — release notes shown on CurseForge. Newest version at the top.
- `CURSEFORGE.md` — the CurseForge project description, pasted by hand (not shipped).
- `.pkgmeta` — packager config (folder name, changelog, files to leave out of the download).
- `.github/workflows/test.yml` — runs the tests on every push. `release.yml` — on a `v*` tag, runs the tests, checks the project ID, then packages and uploads to CurseForge (needs the `CF_API_KEY` secret). `add-to-project.yml` — adds new issues to the project board (needs the `ADD_TO_PROJECT_PAT` secret).

## How Blizzard's Auction House is built (checked against 12.x Blizzard_AuctionHouseUI)

- `AuctionHouseFrame` (`AuctionHouseFrameMixin`, `PortraitFrameTemplate`), 800×538. It's in `UIPanelWindows` as `"doublewide"`, so the panel manager (`UpdateUIPanelPositions`) moves it every time it opens.
- Children are anchored to the frame's edges, so they stretch with it: `SearchBar`, `CategoriesList` (168 wide), `BrowseResultsFrame` (its `ItemList` fills to the right), `ItemBuyFrame`, `CommoditiesBuyFrame`, `ItemSellFrame` / `ItemSellList`, `CommoditiesSellFrame` / `CommoditiesSellList`, `AuctionsFrame` (`AllAuctionsList`, `BidsList`, `ItemList`, `CommoditiesList`), the bottom tabs.
- Every list is an `AuctionHouseItemListTemplate`: `HeaderContainer`, `ScrollBox`, and `tableBuilder` (made on first show). `SetTableBuilderLayout(fn)` marks it dirty; `UpdateTableBuilderLayout()` runs `fn(tableBuilder)` (columns added with `AddFixedWidthColumn` / `AddFillColumn`), `SetTableWidth(ScrollBox:GetWidth())`, `Arrange()`. Blizzard **doesn't** arrange again when the list changes size; `Columns.lua` does (ScrollBox `OnSizeChanged`).
- Browse columns: Price 146 (168 with copper), Name = fill, Lvl 55 (some categories), Available 83 (60 with copper), favourite star 29 (no header).
- Category buttons: 132 wide, `NormalTexture` 136×32 (fixed size), `HighlightTexture` centred. The linear ScrollBox view stretches the buttons to the list's width; their art is stretched by `StretchCategoryButton`.

## Rules the code follows

- **Lua 5.1.** No `goto`, `//`, bitwise operators or `_ENV`.
- **Never buy, bid, post or cancel.** Bid and buyout stay the player's own clicks. The addon doesn't call `C_AuctionHouse` at all (a test checks the source).
- **Coexist.** Only sizes, anchors, widths and the player's own column choices change. Columns are never deleted or replaced, and only hidden or moved when the player asks; tabs (Auctionator's Shopping / Selling / Cancelling / Auctionator) and buttons from other addons are left alone. Columns are known by their header text, so columns added by other addons (e.g. Median) are resized like Blizzard's.
- **Don't taint Blizzard's tables.** Only `hooksecurefunc` (post-hooks) and `HookScript`; never assign fields on Blizzard frames or replace their functions. Original sizes of Blizzard textures are kept in a weak table in `Layout.lua` (`touched`), not on the frames. Calling widget methods and the table builder's column methods (`SetFixedConstraints`, `Arrange`) is fine.
- **Load-on-demand.** Setup runs on `ADDON_LOADED` for `Blizzard_AuctionHouseUI`, or at our own `ADDON_LOADED` / `PLAYER_LOGIN` if another addon (Auctionator) already loaded it. `OnAuctionHouseLoaded` runs once.
- **Blizzard sets the size again** (tab switches, `OnShow`, the panel manager): `SetupLayout` post-hooks `SetSize`, `SetWidth`, `SetHeight`, `SetScale`, `SetDisplayMode`, `OnShow` and `UpdateUIPanelPositions`, and each puts the saved layout back. The `applying` flag stops our own calls from re-triggering the hooks; nothing is re-applied while the grip or title bar is being dragged.
- **Position.** `db.point` is nil until the window is dragged (Blizzard's place is used). Once dragged it's `{ "TOPLEFT", "BOTTOMLEFT", left, top }` on UIParent, in the frame's own scale; `SetScale` converts it so the top left corner stays put. `RememberBlizzardPoint` keeps Blizzard's last place so Reset can move the window back at once (calling `UpdateUIPanelPositions` ourselves would taint the panel manager). `SetUserPlaced(false)` after every drag, so the game's layout cache doesn't fight the saved position.
- **Size limits**: `LIMITS.width` / `LIMITS.height`, and never bigger than the screen at the current scale (`SizeBounds`).
- **Column widths.** Each fixed column's Blizzard width is recorded the first time that column object is seen (`seen`, weak keys; a new layout makes new column objects), before anything changes it, so a reset goes back to it. A divider left of the fill column resizes the column on its left; right of it, the column on its right, so the divider follows the mouse. Dragging stops when Name would drop under `NAME_MIN`; a window made narrower afterwards takes room back from widened columns first (towards Blizzard's width) without changing the saved widths. Columns an addon adds right after Blizzard's layout get their saved width a frame later (`C_Timer.After(0)`).
- **Hidden columns and order** (`ShapeColumns`). `entry.natural` holds every column of a list in the order it was built, hidden ones included (`SyncNatural`: a layout of all-new column objects is a new build; a few new ones among ours came from another addon and go after the column before them). The shown columns, in the saved order, are written back into the table builder's own column list (in place); a hidden column's cells are released with `column:Reset()` and its header hidden, and it goes back into the list when shown. Only named columns move, between the named columns' places, so headerless columns (favourite star) stay put. The fill column (Name) is never hidden. Order is a list of names; a name missing from it (new column) ranks right after the column built before it (`SortNamed`).
- **Row text size** (`rowTextScale`, one of `TEXT_SCALES`, % of each font string's own size; rows grow to `ROW_HEIGHT` × the same %): every font string in a row (3 levels deep, so prices too) gets scaled, after each arrange and on the list's ScrollBox `OnLayout` (rows reused while scrolling). Each font string's own font is kept in `fontBase` (weak keys) and put back on every touched one (pooled cells included) at Default. Row height follows (`SetBoxRowHeight`: the view's `elementExtent` and the shown rows).
- **Category buttons**: Blizzard's `AuctionHouseFilterButton_SetUp` puts fixed texture sizes and its font back on every draw, so `FitCategoryButton` runs right after it (hook) and widens the art by the extra sidebar width and scales the text (`categoryTextScale`). To redraw after a setting change, `StretchCategoryButtons` calls Blizzard's setup again for each button.
- **Saved settings** are checked on load: a value whose type doesn't match its default goes back to the default, numbers are brought inside `LIMITS`, a broken position or column entry is dropped.
- **Chat lines** all start with `Theme.CHAT_PREFIX`: use `AHF.Print`, not `print`.

### Saved variables

- `AuctionHouseForeverDB` (account): `width`, `height`, `scale`, `locked`, `point`, `sidebarWidth`, `rowTextScale`, `categoryTextScale`, `markUnusable`, `browseSort` (`{ kind, reverse }` or nil), `characters` (`["Name - Realm"] = { columns = copy of that character's columns }`, written at login and logout by `RememberCharacter`, read by **Copy from…** / `CopyColumnsFrom`), `showSplash`, `lastSeenVersion`, `schema`.
- `AuctionHouseForeverCharDB` (per character): `columns[listKey] = { widths = { [name] = px }, hidden = { [name] = true }, order = { name, ... } }`, `schema`.

## Testing

Run from the repo root before every commit:

    lua5.1 tests/run.lua

It loads the addon against the fake WoW API and Auction House and covers: loading before and after the Auction House, the size coming back after Blizzard resets it, the panel manager, moving, lock, the corner grip, size and scale limits, dragging dividers (limits, Name minimum, double-click), widths kept across layouts, a column from another addon (Median) and one added late, separate lists, hiding / showing / reordering columns (kept across layouts, Name never hidden, the star keeps its place), row text size, the category list, every settings control, the two-click reset, the Interface Options button, slash commands, damaged saved settings, and that nothing buys, bids or posts. Add a scenario to `tests/run_tests.lua` for any new feature.

Visual check of the layout: `lua5.1 tests/render.lua out.json && python3 tests/render.py out.json outdir` draws the settings tabs and the welcome screen as PNG images (an approximation: plain colours, a wider font than the game's). Needs Python with Pillow.

Things only testable in game: the real frame names on Forever's client (`/fstack` over the Auction House), how the Blizzard art looks when stretched, how bigger row text fits the rows, Auctionator's tabs at bigger sizes, and anything the panel manager does when other windows open beside the Auction House.

## Releasing

1. Make the change, run the tests, add a new section at the top of `CHANGELOG.md` (e.g. `## 1.0.1`), and add the matching entry at the top of `News.lua`.
   If the change shows on the CurseForge project page (features, options, commands), update `CURSEFORGE.md` too (the README, adjusted: no logo, a short install note, full links), and **give the whole updated file in the reply as one Markdown code block**, ready to paste into the project's description (Edit project → Description, Markdown editor). Do this every time the file changes, without being asked. The packager only uploads `CHANGELOG.md` with each file; the description never changes on its own.
2. Commit and push to `main`. The **Tests** workflow must be green.
3. Tag and push the tag: `git tag v1.0.1 && git push origin v1.0.1`. Push a tag only once: pushing it again uploads a second file. Tags containing `beta` or `alpha` upload as Beta/Alpha files.
4. The **Package and release** workflow runs the tests again, then uploads to CurseForge. Check the Actions tab for a green check and the CurseForge Files page (new files go through CurseForge review).

A tag publishes to players, so only tag a tested commit.
